# UI / UX — план улучшений интерфейса

**Контекст:** «Бизнес с Контуром» — браузерный экономический симулятор на React + TypeScript. Десктоп + мобайл. 11 режимов навигации, 14 модалок, 6 вью. Аудитории — предприниматели 25-50 лет в РФ, чаще через мобильный.

Этот документ — приоритезированный план UX-улучшений на основе аудита из `docs/audit/`. Часть пунктов уже закрыта в последних коммитах — отмечено ✅.

---

## P0 — критично, блокирует пользователя

### 1. ✅ Мобильный EventModal не открывался

Раньше события на мобайле блокировали кнопку «Следующий день» без объяснения. Закрыто: `MobileMainScreen.tsx` теперь имеет `useEffect` для авто-открытия и полный `handleEventOption` с `recordEventChoice`, NPC updates, decision log.

### 2. ✅ `<Phone>` wrapper на реальных мобильных

`ResponsiveLayout` оборачивал mobile UI в desktop-preview-компонент, создавая скролл-в-скролле. Закрыто.

### 3. ✅ Сейв не загружался

`STORAGE_KEY` рассинхронизирован между `App.tsx` и `gameStore.ts`. Закрыто.

### 4. ✅ Modal без a11y-семантики

Закрыто: `role="dialog"`, `aria-modal`, `aria-labelledby`, focus trap (Tab/Shift+Tab замкнуты внутри), возврат фокуса при закрытии, `<h2>` заголовок, `aria-label` на close-кнопке.

### 5. ✅ Цвет — единственный канал для прибыли/убытка

Закрыто: `📈/📉` иконка переключается + `formatRubSigned` ставит `+/−` знак. Цвет теперь — третий канал.

## P1 — заметные UX-проблемы

### 6. Operations vs Development — путаница границы (UX-аудит)

**Проблема:** «Купить кассу» живёт в "Управлении", хотя это инвестиция в рост. «Нанять сотрудника» — там же, но ограничено тиром из «Развития» без ссылки.

**Решение:**
- Operations = ежедневное (склад, ассортимент, активные сотрудники, текущая касса).
- Development = капитальные инвестиции (тиры, апгрейды, покупка кассы, найм нового).
- Перенести "Купить кассу" из OperationsView → DevelopmentView.

**Эффект:** ясная ментальная модель «сегодня vs завтра».

### 7. Stage 0 онбординга перегружен intro-шагами

**Проблема:** 3 из 4 шагов — пассивные «Понял →» без действия.

**Решение:** оставить 1 вводный текст; остальные конвертировать в `TutorialMoments` срабатывающие по триггерам состояния (энергия упала, событие пришло, баланс < N).

**Эффект:** игрок начинает играть на ~30 сек раньше; меньше bounce.

### 8. Тач-таргеты на мобайле 32×32 px

**Проблема:** WCAG 2.5.8 (AA) требует ≥24×24, рекомендация — 44×44.

**Решение:**
- Mobile-кнопки header (achievements/help/settings) — 32×32 → 40×40 px.
- Mobile-табстрип кнопки — добавить вертикальный padding до min-height 44px.

### 9. Нет индикатора скрытых табов в mobile-стрипе

**Проблема:** `overflowX: 'auto'` без визуального cue → нарушение SC 1.3.3.

**Решение:**
- Градиент-fade справа/слева на стрипе.
- Точечный индикатор «X / Y табов» под стрипом ИЛИ snap-points.

### 10. NPC спрятаны в одной модалке (creative + UX-аудит)

**Проблема:** Самое сильное конкурентное преимущество (живые NPC × 24 эпизода) живёт только в `NPCRosterModal`. В основном цикле NPC — иконки в списке.

**Решение:**
- Inline-карточка «Что сейчас с NPC» в DashboardView (1-2 ближайших события).
- В WeekResultsOverlay добавить мини-секцию «Реакции NPC» если кто-то изменил `relationshipLevel` за неделю.

**Эффект:** перенос USP из секретного места в основной flow.

### 11. ✅ Bundle size 543 KB → 117 KB initial

Закрыто: lazy-loading модалок + manual chunks (vendor / modals / views / data). Initial paint shrunk in 2×.

### 12. ✅ VictoryModal без CTA в реальный мир

Закрыто: блок «Попробовать в реальности» / «Что могло бы помочь» с прямыми ссылками на `kontur.ru/{service}`.

## P2 — полировка и эмоциональная глубина

### 13. Нет анимаций на пиковые моменты

**Проблема:** VictoryModal появляется мгновенно. Кнопка «Следующая неделя» — без пульса. Достижения — без всплывающего тоста.

**Решение:**
- `canvas-confetti` (3.5 KB gzip) на VictoryModal при `type='victory'`.
- CSS `@keyframes fadeIn` для модалок (60-200ms, легко).
- Achievement toast: `<div role="status" aria-live="polite">` с slide-in справа.
- Все эти эффекты должны автоматически отключаться через `prefers-reduced-motion` (это уже есть глобально).

**Эффект:** игра ощущается «живой», а не Excel-like dashboard.

### 14. Pain Engine UI исчезает после недели 6

**Проблема:** UX-аудит: блок «Без сервисов Контура потеряно» гейтирован `currentWeek <= 6`, тогда как онбординг идёт до W12+. К моменту разблокировки Эльбы и Экстерна мотивация уже не показывается.

**Решение:** показывать блок пока есть незаподключённые разблокированные сервисы. Изменить условие с `currentWeek <= 6` на `unlockedServices.some(s => !services[s].isActive)`.

### 15. Cognitive load на старте — 8 метрик одновременно

**Проблема:** баланс / репутация / лояльность / энергия / качество / тир / цель / неделя.

**Решение:** прогрессивное раскрытие через onboarding stages:
- Stage 0: только баланс + неделя.
- Stage 1: + репутация + лояльность.
- Stage 2: + энергия.
- Stage 3+: всё.

Серые/disabled-карточки для неактивных метрик с tooltip «откроется на N-й неделе».

### 16. KPI sub-labels были 10px и 0.7-opacity

Частично закрыто: подняты до 11px и 0.85-0.92 opacity. Полная фиксация — через token system, чтобы не было inline `rgba()`.

### 17. Модалки не имеют empty state

**Проблема:** AchievementsModal до первой ачивки = пустой контейнер. NPCRosterModal до первой встречи NPC = такой же.

**Решение:** для каждой модалки — illustration + микрокопирайт «здесь появится когда вы …».

### 18. Тосты и нотификации

**Проблема:** «Контур сэкономил X ₽» появляется в углу как inline-div через 3.5 сек. Нет системы.

**Решение:** единый ToastContext с типами `success / warning / info / error`, очередью, `aria-live`, прогресс-баром закрытия. Всё в одном месте.

### 19. Decision Log — нет фильтров

**Проблема:** в late-game (40+ недель) журнал перегружен. Нет фильтров по типу (npc / choice / moral) или impact.

**Решение:** топ-бар с табами «Все / NPC / Дилеммы / Финансовые» + сортировка «Свежие / Решающие».

### 20. Statistics View — статичный дашборд

**Проблема:** просто числа, без графиков. Игрок не видит траекторию баланса.

**Решение:** добавить sparkline-графики для 4 ключевых метрик: баланс, прибыль, репутация, лояльность. Без сторонней библиотеки — простой SVG `polyline`.

## P3 — long-tail и nice-to-have

### 21. Тёмная тема

`tokens.ts` уже структурирован для CSS-переменных, но темной темы нет. `prefers-color-scheme: dark` + переключатель в Settings.

### 22. Storybook для design-system

KHeaderBar, KLeftRail, KIcon, primitives — 12 компонентов без визуального покрытия. `@storybook/react-vite` совместим с Vite 5.

### 23. Visual regression через Playwright snapshots

В рамках того же e2e-сетапа: `expect(page).toHaveScreenshot('victory-modal.png')`.

### 24. Keyboard shortcuts

«N» — следующая неделя, «E» — открыть текущее событие, «Esc» — закрыть модалку (уже есть). Документация в HelpModal.

### 25. Шрифт: исправить Lab Grotesque K → Manrope

**Tech-art аудит:** `tailwind.config.js` ссылается на несуществующий `'Lab Grotesque K'` как primary. По факту используется Manrope. Привести к одному источнику правды.

### 26. Manrope импортируется дважды

В `globals.css` и `design.css`. Оставить один импорт + `<link rel="preconnect">` в `index.html` для FCP.

### 27. Skip-to-content + main landmark

`index.html` мониторует `<div id="root">`. Нужен `<main>` обёрткой и skip-link на старте.

### 28. Правая колонка ServicePanel пустует на мобайле

На viewport < 1024px правый rail сервисов схлопывается в один из mobile-табов. Можно перенести «Активные сервисы» в KStatusBar в виде чипов — постоянно видны.

## Проектные UX-улучшения сверх аудита

### A. Weekly Focus — еженедельный мини-выбор

Сегодня между событиями игра — кнопка-таймер. Game-designer-аудит рекомендует Weekly Focus: 3 опции (Трафик / Качество / Маржа) с легким effect (+5-10%) на текущую неделю.

**Эффект:** decision density растёт без роста сложности.

### B. NPC «следующая глава» — явный cliffhanger

Live-ops-аудит: 24 arc-эпизода — главный retention-крючок, но игрок не знает, что у NPC есть продолжение.

**Решение:** в NPCRosterModal у каждого NPC показывать «Следующая глава ≈ неделя N» (или «Скоро» / «Закончена»).

### C. Объяснение причин роста / падения

В KPI-карточках прибыли/убытка добавить tooltip «Почему?»: разбивка delta vs предыдущий день (выручка ↑, расходы ↑, налоги, экспирация).

### D. «Что я могу сделать прямо сейчас» — quick-actions bar

Sticky-bar внизу с 2-3 рекомендуемыми действиями на основе текущего state: «У вас денег > 200K → улучшить тир», «Низкая лояльность → нанять менеджера», «Доступен новый сервис → подключить».

### E. Replay-режим

После окончания прогона — возможность пройти симуляцию недель в ускоренном режиме (1 неделя/сек) с возможностью паузы. «Что бы было, если…».

## Метрики успеха для UX-итерации

После внедрения P1-P2:
- **Time-to-first-action** при старте: < 30 сек (через анализ `game.business.chosen` − `game.session.started`).
- **Mobile completion rate W1 → W5:** ≥ 60% (через `game.week.completed` события из `analytics.ts`).
- **Conversion на CTA в VictoryModal:** ≥ 8% (через `promo.cta.clicked`).
- **NPC-roster open rate:** ≥ 40% игроков хоть раз открывают (через `modal.opened`).

Все метрики — через privacy-first opt-in буфер `utils/analytics.ts`.
